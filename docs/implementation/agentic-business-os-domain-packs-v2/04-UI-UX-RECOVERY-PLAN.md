# UI/UX 恢复计划

## 1. 目标

界面不是“数据库表的网页镜像”。每个页面必须帮助用户完成一个明确工作：知道当前状态、理解下一步、执行动作、查看结果与证据、从失败恢复。

## 2. 信息架构

一级模块建议：

1. 主管工作台；
2. 工作流；
3. 客户与项目；
4. 数据资产；
5. 问卷；
6. 位置与外勤；
7. 分析与 BI；
8. 智能识别；
9. 财务结算；
10. 账号与权限；
11. 系统与开发者。

一级模块一个 accent 色系，只用于识别边、图标、关键按钮和图表系列；状态色永远统一为 success/warning/error/info，不与模块色混用。

二级菜单对应独立业务能力；三级操作放在 PageHeader、工具栏、步骤条、详情抽屉或工作流节点中，不把所有操作继续塞进侧栏。

## 3. 主页与主管

主页只展示统一 WorkItemProjectionV2：我的待办、待批准、运行中、异常、近期完成、关键指标。每张卡可打开统一任务详情。

“快速目标”正确流程：

1. 服务端保存 goal draft；
2. 打开主管并显示同一文本；
3. 主管给出澄清/计划/成本/权限预览；
4. 用户确认后生成 workflow draft 或 command；
5. 执行后卡片实时显示 run 和下一步。

便签、会话、计划、批准和历史全部服务端持久化；localStorage 只保存非关键 UI 偏好。

## 4. 统一任务详情

任何列表点击后使用同一种详情模式：

- 标题、客户、项目、负责人、状态、SLA；
- 当前节点和下一动作；
- 父子任务与依赖；
- 事件时间线；
- 输入/输出业务摘要；
- 错误、重试、恢复；
- 证据、用量、费用；
- 允许的按钮由 Policy API 返回。

识别任务、问卷任务、外勤任务、报告生成和结算任务均复用这一壳，不再各自发明列表。

## 5. 响应式规则

| 宽度 | 行为 |
|---|---|
| ≥1440 | 可 dock 主管，但用户偏好可记忆；主内容最小 960px |
| 1024–1439 | 主管默认收起为按钮，打开为不透明临时抽屉 |
| 768–1023 | 单列内容，表格切换 card/list，抽屉全屏或 90vw |
| <768 | 底部/顶部模块切换器；不允许只显示无解释色点 |

在 1024 和 768 必须用浏览器真实点击验收，而不是只检查“无横向滚动”。

## 6. 页面状态

每个页面都必须有：loading、empty、permission denied、degraded、error、partial success、offline/retry、success。planned 模块可展示目标、依赖和预计阶段，但不得出现可点击假按钮、假报表或静态成功数字。

## 7. Workflow Studio 人机协作

画布不是唯一入口。非技术用户可以用向导或与 Workflow Agent 对话生成草稿；技术用户可以操作节点。两种方式修改同一个 canonical definition，并显示 diff。

发布前固定显示：校验结果、权限、涉及客户数据、预估运行量、预估费用、失败路径、人工节点、版本差异。

## 8. UI 验收矩阵

每个核心场景至少在 1440×900、1280×800、1024×768、768×1024 验收：

- 无遮挡、无不可见关键按钮、无空白死区；
- 键盘可完成主流程，焦点清晰；
- 文本/状态对比度符合 WCAG AA；
- 400% zoom 后关键信息仍可访问；
- 屏幕阅读器有页面标题、landmark、控件名称和错误关联；
- 浏览器 console 无 error；
- API 错误显示可理解的恢复建议，不暴露堆栈。

原来的精确四视口 `partial` 必须变为真实截图、DOM 断言和交互 `pass`，才能关闭 UI Gate。
