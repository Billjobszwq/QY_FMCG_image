# AI 原生业务操作系统三受众 HTML 推广页设计

> 日期：2026-08-12  
> 交付形态：一个可独立打开的 HTML，内含三套可切换叙事  
> 受众：投资人、生态合作伙伴、潜在客户决策者

## 1. 目标

制作一份正式路演级 HTML 推广材料。页面使用同一套真实架构事实，针对三类受众切换叙事重点和文案；每套叙事都从目标出发，经过智能执行、可信治理和结果交付，最终由反馈进入下一轮优化，形成完整逻辑闭环。

页面必须便于用户后续自行修改文案，不披露核心技术实现。

## 2. 核心主张

> 不是让人围着软件流程工作，而是让系统围绕业务目标组织工作。

系统对外统一定位为 **AI 原生业务操作系统**。传统软件体验只作为认知背景，不作为页面主角，也不在主标题中反复出现。

## 3. 三套叙事

### A｜投资人愿景版

叙事顺序：

1. 新范式：企业软件从功能供给进入目标执行时代。
2. 结构性问题：组织能力、数据和人员被分割，目标无法自行推进。
3. 总体架构：智能执行内核组织能力网络，可信底座提供业务边界。
4. 增长飞轮：更多运行产生更多反馈，反馈经治理形成更强能力，更强能力支持更多场景。
5. 商业价值：从单点功能收入走向能力、运行、行业包和生态协作形成的多层价值。
6. 扩展空间：同一内核进入更多行业场景，但不重复建设平台底座。

闭环：`市场需求 → 业务目标 → 运行与交付 → 反馈资产 → 能力升级 → 更多客户与场景 → 新需求`。

### B｜生态合作伙伴版

叙事顺序：

1. 共同目标：伙伴不再只交付接口或单点能力，而是共同完成客户结果。
2. 合作入口：行业知识、业务服务、数据产品、执行资源和客户系统均可进入能力网络。
3. 能力协同：智能执行内核按客户目标组合平台能力与伙伴能力。
4. 可信治理：身份、授权、证据、审批、用量与审计贯穿联合交付。
5. 联合成果：结果、责任、证据和价值贡献均可核对。
6. 生态反馈：真实交付反馈进入评估，形成更成熟的联合方案和新市场机会。

闭环：`客户目标 → 能力接入 → 联合执行 → 可信交付 → 价值确认 → 方案沉淀 → 更多合作机会`。

### C｜潜在客户转化版

叙事顺序：

1. 业务困境：人力消耗在找入口、搬数据、催流程和处理重复例外。
2. 新体验：客户只需提出目标，系统形成可解释的执行计划。
3. 主动执行：系统组织跨领域能力和参与者，持续观察并动态调整。
4. 人机守门：关键动作由人批准，过程有事实、有证据、可暂停和恢复。
5. 结果交付：交付问题清单、执行证据、改进进度、经营洞察和可核对成本。
6. 持续优化：本次结果转化为下一轮目标的更好起点。

闭环：`业务问题 → 提出目标 → 智能执行 → 人机决策 → 可验证结果 → 反馈优化 → 下一轮目标`。

## 4. 共用逻辑闭环

三版必须共享同一条不可断裂的业务运行逻辑：

```text
业务目标
  ↓
理解与规划
  ↓
组织人、能力与数据
  ↓
持续执行与动态调整
  ↓
人工审批与可信治理
  ↓
交付可验证业务结果
  ↓
反馈、评估与版本优化
  └──────── 回到下一轮目标
```

任何章节都必须能回答：输入是什么、由谁或什么推进、受什么约束、产生什么结果、结果如何进入下一轮。

## 5. 页面信息架构

### 5.1 全局区域

- 品牌区：AI 原生业务操作系统和核心主张。
- 受众切换器：投资人、生态伙伴、潜在客户。
- 章节导航：当前版本六个章节，可点击跳转。
- 演示模式：一次只显示一个章节，支持上一页和下一页。
- 浏览模式：纵向显示当前版本全部章节。
- 编辑提示：说明文案集中在页面内的 `CONTENT` 数据对象中，便于自行修改。

### 5.2 章节结构

每个版本固定六章，每章包含：

1. 一句核心结论；
2. 一张与该结论直接对应的正式图示；
3. 三条价值说明；
4. 一句承上启下的过渡文案。

切换受众时，标题、章节、图中重点、价值文案和结尾行动引导一起切换，避免出现文案与图形不一致。

## 6. 图形系统

### 6.1 总体架构图

采用严格四层网格：

1. 体验入口；
2. 智能执行与持续进化；
3. 可组合业务能力网络；
4. 可信业务底座。

生态连接和灵活部署作为左右边界，不混入核心层级。

### 6.2 业务运行轨道

使用一条连续、有明确箭头方向的主轨道表示目标到结果。人工审批使用琥珀色菱形节点，可信治理使用青绿色护栏，反馈使用回到起点的闭合曲线。

### 6.3 能力网络

中央为智能执行内核，周围为可组合能力。连线只表达“可被组织”，不披露调用顺序、内部依赖和实现协议。

### 6.4 飞轮和反馈环

所有循环必须有明确入口、阶段、出口和回流条件，不使用仅为装饰的圆环。投资人版表现增长飞轮，伙伴版表现联合方案飞轮，客户版表现业务改善闭环。

### 6.5 图例

- 电光蓝：智能理解与执行；
- 青绿色：可信治理与业务事实；
- 琥珀色：人类判断与审批；
- 紫色：价值结果与能力进化；
- 灰色：外部背景、既有系统或未被组织的状态。

颜色必须与形状和标签共同表达含义，不能只靠颜色区分。

## 7. 视觉方向

- 主题：深海作战图，而不是软件后台或普通企业宣传模板。
- 画布：深海军蓝背景，极细坐标网格和低透明度业务轨迹构成空间感。
- 排版：大标题具有资本市场路演感；正文使用清晰的中文无衬线；数据、编号和图例使用窄体辅助字体。
- 结构：最大内容宽度稳定，采用十二列网格；章节上下留白一致，所有节点对齐到同一基线。
- 形状：核心节点使用切角矩形，人工节点使用菱形，结果节点使用双边框，底座使用连续承托带。
- 连线：统一线宽、箭头尺寸、转折半径和语义；禁止箭头穿过文字、节点重叠或无来源连线。
- 动效：仅在切换版本、进入章节和闭环回流时使用短促动画；尊重减少动态效果设置。
- 响应式：桌面用于路演，移动端改为单列轨道；不通过缩小文字硬塞固定宽图。

页面的记忆点是贯穿三版的 **目标—结果闭环轨道**：切换受众时，轨道结构不变，叙事重点和节点说明随之改变，体现同一架构服务不同价值关系。

## 8. 可编辑文案设计

所有可变内容集中在一个清晰的 JavaScript `CONTENT` 对象：

```javascript
const CONTENT = {
  investor: { label: '投资人愿景版', hero: {}, sections: [] },
  partner: { label: '生态合作伙伴版', hero: {}, sections: [] },
  customer: { label: '潜在客户转化版', hero: {}, sections: [] }
};
```

每个章节使用一致字段：`eyebrow`、`title`、`thesis`、`diagram`、`values`、`transition`。用户修改文案不需要调整布局代码。

## 9. 对外披露边界

### 可展示

- 目标驱动、智能执行、人机协同、结果闭环和持续进化的产品体验。
- 智能执行内核、能力网络、可信底座、行业扩展和生态连接等产品级概念。
- 统一身份、权限、事实、证据、审批、用量、价值和审计能力。
- 云端、客户环境和混合部署等部署选择。

### 不展示

- 内部编排语法、状态结构、决策规则和执行机制细节。
- 具体模型、组合方式、参数规则、指令内容和评估方法。
- 数据结构、内部接口、服务地址、密钥和基础设施品牌。
- 训练样本策略、能力升级门槛、安全判定条件和其他竞争壁垒。

## 10. 交付与验证

### 交付

- 一个独立 HTML 文件，内含三套叙事切换。
- 默认进入投资人愿景版。
- 可直接用浏览器打开，无需服务端和网络资源。
- HTML 内包含文案修改说明。

### 验证

- 三版各六章，切换后内容、导航、图形重点和行动引导同步变化。
- 三个闭环均能从目标回到下一轮目标，不存在断点或无来源节点。
- 在 1440px、1024px、768px 和 390px 宽度无横向溢出、节点重叠或文字裁切。
- 键盘可操作受众切换、章节导航和演示控制。
- 页面在禁止联网时仍完整显示。
- 敏感技术词和内部实现信息扫描无结果。
- 文案数据与渲染逻辑分离，修改 `CONTENT` 后无需修改结构代码。
