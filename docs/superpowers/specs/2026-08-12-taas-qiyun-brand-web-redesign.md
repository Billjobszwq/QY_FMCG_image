## 1. 品牌层级

页面使用以下固定层级：

1. **核心概念：TaaS｜词元即服务**
2. **产品定位：AI 原生业务操作系统**
3. **英文释义：Token as a Service**
4. **公司识别：QIYUN Logo / DECISION · DATA · DRIVE**

中文承担解释、叙事和说服；英文只承担概念全称、辅助标签、Logo 原有口号和少量章节索引。QIYUN Logo 是品牌背书，不是首屏主角。

## 2. TaaS 对外定义

### 2.1 一句话定义

> 词元不再只是智能模型处理内容的计量单位，而是驱动业务理解、决策、协同与执行的智能生产要素。

### 2.2 完整定义

> TaaS｜词元即服务，将词元所承载的理解、推理与行动能力，组织成可治理、可计量、可持续进化的业务服务，并最终交付可验证的业务结果。

### 2.3 必须避免的误解

- TaaS 不是单纯售卖计算量或调用额度。
- 词元不是页面中可孤立购买的技术单位，而是智能生产力的基础载体。
- 商业价值不止来自词元数量，而来自词元驱动的业务运行、能力调用、人工协同与结果交付。
- 页面不得暗示每个词元独立执行某个具体业务动作；应表达为词元共同承载理解、推理、上下文和行动指令。

## 3. 主逻辑闭环

全站使用同一条七阶段闭环：

```text
业务目标
  ↓
可执行意图
  ↓
词元驱动理解与决策
  ↓
组织人员、数据与能力
  ↓
持续执行与人工守门
  ↓
可验证业务结果
  ↓
反馈、评估与能力进化
  └──────── 回到下一轮目标
```

这条闭环同时解释：

- 词元如何进入业务，而不是停留在内容生成；
- 智能如何被组织成持续运行的系统；
- 为什么人工判断、业务事实和可信治理不可缺失；
- 一次业务结果如何成为下一轮目标的更高起点。

## 4. 三套受众叙事调整

### A｜投资人愿景版

主问题：TaaS 开创了什么新类别，为什么具备平台价值和增长空间？

叙事链：

`词元成为智能生产要素 → 智能生产力进入业务运行 → 统一架构组织能力 → 运行沉淀反馈资产 → 能力和场景共同增长 → 形成新商业类别`。

重点文案：

- 从“按功能交付软件”走向“按目标组织智能生产力”。
- 从技术调用单位走向业务价值载体。
- 词元、能力、运行和结果形成多层价值关系。

### B｜生态合作伙伴版

主问题：伙伴如何进入 TaaS 网络并共同完成客户结果？

叙事链：

`客户目标 → 词元理解上下文 → 选择并组织伙伴能力 → 联合执行 → 可信交付 → 价值确认 → 联合方案进化`。

重点文案：

- 伙伴能力不只是被调用，而是进入可治理的业务运行网络。
- 词元承载目标、上下文与协同意图，连接平台能力和伙伴专业能力。
- 交付结果、证据和价值贡献均可确认。

### C｜潜在客户转化版

主问题：TaaS 如何让客户获得更好的工作体验和业务结果？

叙事链：

`提出业务目标 → 词元理解目标和上下文 → 系统形成计划 → 组织人、数据与能力 → 持续执行与人工判断 → 交付完整结果 → 反馈优化下一轮`。

重点文案：

- 客户无需理解词元技术细节，只需要看到目标如何变成结果。
- TaaS 的体验不是多一个对话框，而是系统开始主动组织工作。
- 人聚焦目标、例外和判断，系统承担协调、推进和记录。

## 5. Logo 使用规则

### 5.1 资产

- 深色背景：`<design-assets-root>/logo-deep2.png`
- 浅色背景：`<design-assets-root>/logo-white.png`

最终 HTML 必须复制并内嵌所需 Logo 数据，保证文件单独发送后仍能离线显示。不得依赖上述绝对路径运行。

### 5.2 页面位置

- 顶部导航左侧显示横向 QIYUN Logo，视觉面积不超过导航区域的 18%。
- 首屏不再次放大完整 Logo。
- 首屏主标题始终是 `TaaS｜词元即服务`，副标题是 `AI 原生业务操作系统`。
- Logo 原口号保持原样，不在正文重复翻译或重新解释。

### 5.3 清晰度和安全区

- 保持原始长宽比，禁止拉伸、变色、裁切标志或重排文字。
- Logo 四周最小安全区为标志图形高度的四分之一。
- 深色版 Logo 本身带有深色画布，页面应通过一致背景融合，避免出现明显方形贴片。

## 6. 视觉语言

### 6.1 品牌色提取

- QIYUN Deep：`#060C17`，主背景与可信空间。
- Token Violet：`#7200FF`，理解、推理与智能密度。
- Decision Red：`#F52B61`，问题、触发与关键变化。
- Value Gold：`#FFBE18`，人工判断、价值确认与结果节点。
- Drive Cyan：`#08C9BE`，执行、协同和持续驱动。
- Paper White：`#F4F7FC`，主要文字和浅色导出背景。

页面不铺满彩虹渐变。完整渐变只用于“词元流”这一签名元素；其余图形使用单一语义颜色和低透明度底色。

### 6.2 字体

- 中文标题：现代几何无衬线，优先使用系统可用的 `PingFang SC`、`Microsoft YaHei`。
- 英文与数字：`Avenir Next`、`Helvetica Neue` 或系统无衬线。
- 禁止使用书法体、仿宋体或装饰性衬线体作为大标题。
- 中文标题字重 600–700，正文 400，英文辅助标签使用字距而不使用过细字体。

### 6.3 签名元素：词元流

页面以 Logo 环形渐变为灵感，设计一条从紫色理解、红色触发、金色判断到青色执行的连续“词元流”。

- 词元流从业务目标进入智能执行核心；
- 在人工守门处短暂汇聚为金色判断节点；
- 在结果区转为青色持续驱动；
- 反馈段以紫色返回下一轮目标；
- 动画只表达一次完整流动，不持续循环干扰阅读。

## 7. 页面改造

### 7.1 顶部导航

- 用真实 QIYUN Logo 替换当前自制菱形图标和文字标识。
- 保留三受众切换器，但颜色和选中态改为 Logo 渐变细线。
- 移动端优先显示主 Logo，受众切换放在第二行。

### 7.2 首屏

中文主标题：

```text
TaaS｜词元即服务
```

产品定位：

```text
AI 原生业务操作系统
```

英文辅助：

```text
Token as a Service
```

首屏右侧不使用抽象同心圆堆叠，改为一张正式“目标—词元—能力—结果”动态关系图。图形必须包含输入、处理、治理、输出和反馈回路。

### 7.3 闭环轨道

- 七个节点使用正式统一几何规范。
- “词元驱动理解与决策”为核心高亮节点。
- 人工守门使用金色菱形。
- 结果使用双边框。
- 反馈曲线明确回到“业务目标”，不可停在页面边缘。

### 7.4 六类章节图

保留范式、摩擦、总体架构、执行、飞轮和价值六类图，但统一加入：

- 清晰输入与输出；
- 词元在该图中的角色；
- 可信治理边界；
- 结果如何进入反馈；
- 完整箭头和图例。

## 8. 文案结构

`CONTENT` 对象增加以下稳定字段：

```javascript
brand: {
  concept: 'TaaS｜词元即服务',
  positioning: 'AI 原生业务操作系统',
  english: 'Token as a Service'
}
```

每套受众文案必须至少一次完整解释 TaaS，但不得在每章重复定义。首次出现提供定义，后续使用“词元驱动”“智能生产力”“业务运行”等更自然的表达。

## 9. 对外披露边界

可以披露：

- 词元作为智能生产要素的产品概念。
- 从目标理解到业务结果的完整运行机制。
- 人机协同、业务事实、可信治理、价值计量和持续进化。
- 三类受众对应的产品、生态与商业价值。

不得披露：

- 词元内部如何被具体模型分配、路由或转换为执行指令。
- 具体模型、参数、上下文组织、指令设计和评估门槛。
- 内部数据结构、接口、基础设施和安全判定条件。
- 能够推导核心竞争实现的运行细节。

## 10. 验收标准

- 首屏 3 秒内能识别 `TaaS｜词元即服务` 和 `AI 原生业务操作系统`。
- Logo 清晰可见但不抢主标题，深色版无明显方形背景边界。
- 中文信息量明显高于英文，英文不承担关键解释。
- 三套受众内容均包含 TaaS 定义或自然承接，并保持逻辑闭环。
- 所有主要图形能回答输入、执行、治理、结果和反馈五个问题。
- 页面使用 Logo 品牌色但不呈现大面积彩虹渐变。
- 在断网和脱离原始 Logo 路径时仍完整显示。
- 1440px、1024px、768px 和 390px 宽度无溢出、裁切或节点重叠。
- 专项测试覆盖品牌字段、TaaS 定义、Logo 内嵌、闭环词汇和敏感信息边界。
